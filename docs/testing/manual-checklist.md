# 手工测试清单（批次 7 收敛）

> 逐项手测后在结果栏勾选；发现问题请按文末格式记录。

## 测试前准备

1. **备份数据库**：复制 `.local/data/music.db` 到安全位置（首次启动新版本会执行尚未应用的迁移（当前库在 014 时为 015～031），并在 Go 端清理标签控制字符，见文末"升级提示"）。
2. **建议先填 MusicBrainz 联系方式**：管理 → 数据来源 → MusicBrainz 卡片 → "联系邮箱或项目地址"。未填写时 User-Agent 回退为项目仓库地址，可用但不推荐长期如此。
3. **耗时预期**：首次全量增强（管理 → 自动增强 → 范围"全部（专辑、曲目及作品）"）每张/每首/每作品都会请求 Bangumi，请求间隔默认 500ms（可用 `MUSIC_SERVER_BANGUMI_INTERVAL_MS` 调整，200～10000ms）；曲目多时要跑较久，可随时点"停止"。被限流时本轮会立即停止（见"限流表现"）。
4. 确认服务以正常媒体库路径启动并完成一次扫描。

## 9. 系列管理

- 入口：管理 → 系列管理（/admin/series）
- 步骤：①“新建系列”：填系列名（可选）、选择 1～2 部作品 → “创建系列”；②详情页“加入作品”搜索并“加入系列”；③对成员点“移出”（提示“移出后该作品不再自动归组”）；④“合并系列”：搜索要并入的系列，选择“合并后的名字”（保留《当前系列名》/保留被并入系列的名字/新名字/自动（按规则））→“合并到本系列”；⑤改名：“系列名”输入框 →“重命名”（改名的系列显示“已改名”，自动流程不再覆盖）；⑥“解散系列”
- 预期：各操作即时生效并有提示；移出/改名是用户意图，自动归组不再抢占
- 易错点：**改过名的系列只剩 1 部作品时会保留**（与允许 1 部作品建系列一致），0 部时才删除；未改名的自动系列少于 2 部仍会解散；只剩 1 部自动成员的改名系列，下次自动归组候选不足 2 部时也会保住这部作品（不会被删成空系列），候选足够时会被认领并补回成员，名字始终保持用户所改
- 易错点（已知限制 D-68 副作用）：被拆出且失去引用的作品会一直留在作品列表的“受保护但无引用”中，需要手动到作品页删除
- 易错点（已知限制 D-20）：被拆出或解散的作品如果之后被删除，同一 Bangumi 条目经由其他专辑重新生成的作品可能被自动归组重新拉回系列（系列锁按作品记录，不跨重建）；遇到时在系列管理页再次移出/解散即可
- 结果：☐ 通过 / ☐ 问题：____

## 10. 系列建议（跨媒体、续集）

## 13. 限流表现（如何观察）

- 触发：来源返回 429 或带 Retry-After 的 503（真实限流或大量请求后）
- 预期：
  - 后台任务（自动增强、艺术家匹配、系列归组）立即停止本轮，任务记录显示"<来源> 限流（429），已停止本轮，约 N 分钟后可重试"，状态为失败但**限流不计入连续失败熔断**；
  - 退避期内交互操作（手动匹配/刷新简介）立即提示"<来源> 限流中，约 N 分钟后再试"，不再实际发请求；
  - 匹配先成功、图片/简介后限流时提示会明确"已（自动）确认匹配"而非失败；
  - 退避过后（默认 60 秒起、上限 10 分钟，按 Retry-After）重跑任务即可继续，缓存使命中条目不再重复请求
- 结果：☐ 通过 / ☐ 问题：____
