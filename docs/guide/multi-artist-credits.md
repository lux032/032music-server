# 合作曲目与多艺术家署名

## 本次修复

MusicAutoTagger 旧版将合作曲目的名字写成单个 `ARTIST=A, B`，并把 MusicBrainz Artist ID 写成分号分隔列表。仅有展示文字时，客户端无法判断它是组合名还是多人署名。

服务端现在优先读取结构化 `ARTISTS` / `ALBUMARTISTS`，兼容 Vorbis 多值、ID3v2.3/v2.4 的 TXXX 与 NUL、MP4 自定义字段。曲目艺人与专辑艺人分别读取，不用演唱者覆盖发行署名。

对旧 MusicAutoTagger 标签，仅在以下条件全部满足时恢复多人曲目关系：

- 存在至少两个不同且有效的 MusicBrainz Artist UUID。
- 展示文字按旧刮削器的 `, ` 分隔后，人数严格等于 UUID 数量。
- 分隔后没有空名字或重复项。

无法明确对应时保持原署名，不按 `&`、`feat.` 等符号猜测。名字本身有逗号且造成数量不匹配时，也不自动拆分。新刮削器已写入独立姓名列表，可避免这类歧义。

## 升级与现有曲库

1. 先备份服务端数据库，再升级服务端。本次新增迁移 067-069，启动时自动应用。
2. 执行一次**完整扫描**。增量扫描会跳过未改动文件，不能保证修正已有曲目。
3. 核对一首合作曲目的 API `artists` 数组，应该有多个独立 ID。曲目 ID、歌单、曲目收藏和播放记录不应改变。
4. Android MusicBridge 执行完整曲库刷新；Rust 重新进入曲目/专辑页，或重启重新加载。客户端旧队列在收到更新的曲目数据时刷新署名，不重开播放会话。
5. 对不能自动识别的曲目，使用下方人工修正。

不需要为了这个修复重新下载音频，也不要求先重写所有音乐文件。新刮削器只影响之后实际执行写标签的文件，不会主动重写已处理文件。

## 旧幕后署名兼容转换

作词、作曲、编曲、制作默认按结构化复数字段（COMPOSERS / LYRICISTS / ARRANGERS / PRODUCERS）及容器多值字段读取，不自动按英文逗号拆人。演唱者和专辑艺人的规则保持独立。

旧 MusicAutoTagger 文件只有逗号拼接文字时，请先备份数据库，再在扫描页展开“旧文件兼容：拆分幕后署名”，勾选风险确认，点击“兼容旧幕后署名并完整重扫”。这次手动扫描才会按英文/中文逗号拆分没有明确列表的幕后署名。名字本身含逗号可能被误拆，不能当作日常扫描入口。

兼容结果保存在服务端，与原始标签指纹绑定。相同标签的普通重扫复用已经确认转换的结果；源标签变化后按正常规则重新读取，不自动对新标签继续猜拆。明确的结构化字段始终优先，转换不修改音乐文件。没有常驻全局开关，也没有为自动扫描启用激进规则。

新刮削器保留幕后人员列表，写入原生多值和复数结构化辅助字段；之后正常扫描即可识别，不需要兼容转换。Rust / Android 复用已有 credits 数组，不需要为此新增协议。

## 个人页的合作作品

专辑归属与歌曲合作分开判断，不再因为专辑里有多人合唱，就把整张专辑归为合作发行：

- 专辑艺人只有 A，即使其中有 A + B 合唱，在 A 页仍为个人发行（`personal`），在 B 页为参与作品（`appearance`）。专辑、单曲与 EP 均按此规则处理。
- 非合辑发行的专辑艺人为 A、B 共同署名时，在双方页为合作发行（`collaboration`），不要求曲目必须合唱。
- VA / Various Artists 合辑中的合唱，在各演唱者个人页为参与作品（`appearance`）；多人专辑署名的合辑也保留现有参与作品分类。单人署名的精选集仍是本人的个人发行。

歌曲本身保留全部 `primary` 演唱者关系，双方仍能查询到合作曲目。分类按读取时的专辑关系计算，不修改音乐文件或数据库署名；本项修复部署后重新进入艺人页即可生效，不需要为分类再次重扫。

## 人工修正

入口：专辑页曲目署名后的“修正演唱者”，或歌曲列表“编辑与更多操作”中的同名入口。

- 搜索选择已有艺术家，按输入位置决定顺序。清空旧位置可移除原合作署名。
- 点击“预览修改”，核对后确认。
- 本期是**单曲修正**，没有全库自动替换和批量写入。
- 不修改音频文件、专辑署名或幕后角色；完整重扫仍保留人工结果。
- “恢复默认”关闭人工覆盖并使用最新扫描的底层署名。
- “撤销最近操作”恢复上次人工配置，预览会显示恢复后人员；标签在此期间变更时，使用最新底层结果。
- 预览之后曲目关系变化、目标艺术家合并时需要重新预览。重复提交旧表单不会重复应用。

原合作署名实体不会重定向到其中一位个人，不会把它的头像、简介、外部身份或艺术家收藏复制给个人。它仍有专辑署名等关联时会继续出现，这是预期行为。

艺术家合并回退采用保守保护：合并之后发生任何新的演唱者人工修改时拒绝回退；旧合并没有版本记录且已存在人工修正时也拒绝直接回退，避免覆盖后续编辑。

## 限制

- 人工纠正暂时只能选择已有艺术家。
- 未读取 MusicBrainz 在线资料来自动猜测旧文件的姓名顺序。
- 没有新增 API 版本或同步协议。Android 需要完整刷新才能发现旧 ID 的变化。
- 未在真实曲库执行扫描或修正，升级后请先以一首样本验收。
