# 作品关联功能说明（给使用者看的大白话版）

这份说明讲清楚"作品关联"这套功能做了什么、哪些事是自动的、哪些以你的操作为准、结果不对时去哪里改。技术细节和决策记录在 `docs/design/works-association.md`，日常使用不需要看。

---

## 一、它解决什么问题

你的音乐库里有很多动画、游戏的歌：OP、ED、插入歌、角色歌、原声集。这套功能把**音乐**和它所属的**作品**（某部动画、某个游戏、某部剧场版）连起来，再把同一系列的作品（第一季、第二季、剧场版、游戏版）归成一个**系列**。

连好之后，你可以：
- 在专辑页看到这张专辑属于哪部作品，每首歌是 OP 还是 ED；
- 在作品页看到这部作品的所有相关专辑和歌曲；
- 在作品列表里按系列折叠浏览，或者只看动画、只看游戏。

## 二、三层东西

| 层 | 是什么 | 例子 |
|---|---|---|
| 音乐 | 专辑、曲目 | 《紅蓮華》单曲 |
| 作品 | 一部动画、游戏、剧场版等 | 鬼滅の刃 竈門炭治郎 立志編 |
| 系列 | 同一个 IP 的多部作品 | 鬼滅の刃（立志編、無限列車編、遊郭編……） |

一部作品最多属于一个系列；系列只有一层，不再往下分。

## 三、哪些事是自动做的

数据主要来自 **Bangumi**（番组计划），辅以曲目标签本身的信息。自动流程会：

1. **从标签猜作品**：比如标签里写着"TVアニメ『XXX』オープニングテーマ"，就建立本地作品并关联。
2. **去 Bangumi 反查**：用专辑名、曲目名去 Bangumi 找对应的音乐条目，再顺着条目找到它关联的动画或游戏。
3. **纠正作品类型**：Bangumi 说它是剧场版，就把类型改成电影。
4. **自动归系列**：顺着 Bangumi 上"续集 / 前传"关系，把多季动画归到同一个系列。
5. **生成系列建议**：跨媒体的关系（比如动画和它的游戏、正篇和总集篇）**不会自动合并**，只放进审核页让你决定。

什么时候跑：每次扫描完成后，如果你在"数据来源"里开了自动匹配，就会自动跑一轮；也可以在"管理 → 自动增强"手动启动。查过的结果会缓存 30 天，所以第二轮开始基本不再请求外网。

证据足够明确时自动确认；不够明确的放进审核页等你决定。

## 四、你的操作永远优先

这是整套功能最重要的原则：**人工 > Bangumi > 本地推测，并且你的决定会被永久记住。**

- 你**拒绝**过的关联，之后重扫、重算都不会再自动加回来。
- 你**手动加**的关联，自动流程不会删掉。
- 你**改过名**的系列，自动流程不会再改它的名字，只剩 1 部作品时也会保留。
- 你从系列里**移出**的作品、**解散**的系列，这些作品以后不再参与自动归组。
- 你手动锁定的**作品类型**，Bangumi 不会再改。

所以不用担心"改了又被自动流程改回去"。

## 五、你平时会用到的地方

| 想做什么 | 去哪里 |
|---|---|
| 处理待审的关联和建议 | 管理 → **作品关联审核**（导航上的数字就是待审总数） |
| 看/改一张专辑关联了哪些作品 | 专辑详情页右侧"作品关联" |
| 看/解除一部作品关联的曲目 | 作品详情页"曲目用途" |
| 整理系列（新建、加入、移出、合并、改名、解散） | 管理 → **系列管理** |
| 按类型浏览作品 | 作品列表的"类型"筛选 |
| 手动跑一轮增强 | 管理 → 自动增强 |
| 填联系方式、开关数据源 | 管理 → 数据来源 |

审核页有 4 个 Tab：
- **专辑候选**：这张专辑可能属于哪部作品；
- **曲目候选**：精选集里某首歌可能属于哪部作品；
- **作品对齐候选 · 身份匹配**：确认本地作品与哪个 Bangumi 动画／游戏条目是同一个作品，不是给音乐添加关联。每个具体作品只绑定一个条目，专辑和曲目仍可以关联多部作品；
- **系列建议**：哪两部作品应该放进同一个系列（每条都会用一句话说明关系，例如"《ヒノカミ血風譚》是《立志編》的游戏"）。

## 六、结果不对时怎么办

| 看到的情况 | 怎么改 |
|---|---|
| 专辑关联错了作品 | 专辑页"解除关联"（会被记住），需要的话再"添加专辑关联" |
| 某首歌挂错了作品 | 作品页"曲目用途"里点"解除" |
| 该关联的没关联上 | 专辑页手动"添加专辑关联"；或去审核页看是否在待审里 |
| 作品类型不对 | 作品页修改类型（改后自动流程不再覆盖） |
| 两个系列其实是一个 | 系列管理 → 系列详情 → "合并系列" |
| 某部作品不该在这个系列 | 系列详情页对它点"移出" |
| 审核建议不合理 | 点"拒绝"，以后不会再出现 |

### 作品身份匹配怎么处理

- 先点“查看关联专辑与曲目／检查本地作品”，确认本地名字确实代表某一部动画或游戏，而不是音乐专辑名。音乐专辑的 Volume 2 不等于动画第二季。
- “匹配分”是规则得分，不是正确概率；候选会显示标题、类型、年份等匹配依据。仅类型一致的搜索结果不再进入审核。
- 有正确答案时点“确认是同一作品”：补全作品资料，保留原来的音乐关联，自动关闭其余候选。系统不会逐首验证原来的歌曲归属。
- 全部不对时点“以上都不是”：一次忽略当前这组候选，不删除作品或音乐关联。同一条目不会因普通重跑恢复待审，但以后仍可能出现新的候选；这不是永久停用作品匹配。
- 条目已被其他本地作品绑定时，先通过卡片链接检查现有作品，不能重复绑定。当前尚无作品合并或解除身份绑定的完整 Web 流程，不要用删除作品来代替合并。

## 七、已知的小问题（遇到了不用慌）

- **改名后别名挂错**：你把动画 X 改名成 Y、而库里还没有游戏 X 时，精选集里标注"ゲーム『X』"的歌可能挂到 Y 上。手动解除即可；游戏 X 入库后会自动纠正。
- **标题带 `&` 的合辑**：例如 `EIGHTY-SIX REARRANGE & OUTTRACKS CD` 不会自动关联，需要手动关联一次。
- **续集链暂时分成两个系列**：一个系列里只剩你手动加的作品时，新出的季可能先被归到一个新系列，审核页会出现"续集"建议，接受即可合并。
- **拆出的作品被删除后重建**：你移出系列的作品如果后来被删除、又从别的专辑重新生成，可能会被自动归回系列，再移出一次即可。
- **限流**：Bangumi 或 MusicBrainz 返回"请求过多"时，本轮任务会立即停止，并提示大约几分钟后可以重试。这属于正常保护，稍后重跑就好。

## 八、第一次用之前

1. **备份** `.local/data/music.db`。新版本第一次启动会自动升级数据库，库大时启动会慢一点。
2. 在"管理 → 数据来源 → MusicBrainz"里填一个**邮箱或主页地址**（外部服务要求能联系到使用者）。
3. 按 `docs/testing/manual-checklist.md` 逐项试用，遇到问题记下页面地址、操作步骤和截图。
