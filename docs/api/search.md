# 统一搜索与歌手搜索别名

`GET /api/v1/search?q=星街彗星` 只查询本地曲库，不在搜索时调用外部服务。
需要 API Bearer Token 或管理员会话。搜索请求最多执行 10 秒；超时返回 HTTP 503，JSON 接口的错误码为 `search_timeout`。Web 入口为 `/admin/search`，主页搜索和导航均可进入。

## 查询与结果

- `q`：最多 200 个字符；首尾空格忽略。空查询返回空结果，不遍历曲库。
- `category`：省略时聚合预览；可指定 `artists`、`albums`、`tracks`、`composers` 获取单类完整分页结果。
- 单类查询使用 `limit`（默认 100，最大 500）、`offset`（默认 0）。聚合预览固定展示歌手 5、专辑 6、歌曲 10、作曲家 5 项。

返回 `query`、`category`、`bestMatch` 及四个同名分区。每个分区为：

```json
{"items": [], "total": 0, "limit": 5, "offset": 0}
```

单类模式下其他分区为空。`total` 是该类全部匹配数量，不受预览数量限制。
所有结果只包含有可用音频的本地内容，合并后的歌手使用目标 ID。支持平假名／片假名变体；`%`、`_` 等按字面匹配，不提供拼音、自动翻译或错字纠正。

歌手匹配当前名称、原名称、读音、本地历史别名、人工搜索别名以及已绑定外部资料中的名称和别名；待确认候选不参与。被合并歌手的名字和别名会继承到目标歌手，回退合并后恢复原归属。

专辑匹配标题、读音，以及匹配歌手担任专辑艺人或参与演唱可见歌曲的关联。歌曲匹配标题及演唱关系；仅当曲目没有明确演唱者时回退专辑艺人，避免一首合作曲目召回整张合辑的歌曲。作曲家分区只显示在可见歌曲中有 `composer` 署名的人员，入口为 `/admin/credits/{id}?role=composer`。

排序为完整匹配、前缀匹配、包含匹配、歌手关联结果；专辑标题直接命中优先，关联结果内个人专辑优先于合作和合辑。最后按名称和 ID 稳定排序。`bestMatch` 含 `type`（分区名）、`id`、`title`、`subtitle`、`imageUrl`，歌曲额外含 `albumId`。同分时依次优先歌手、歌曲、专辑、作曲家；多个歌手同分时不强选歌手。没有直接匹配或单类分页时为 `null`。

## 人工搜索别名

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/v1/artists/{id}/search-aliases` | 返回 `{items:[{id,artistId,value}]}`，包含合并继承的人工搜索别名 |
| POST | `/api/v1/artists/{id}/search-aliases` | JSON `{ "value": "星街彗星" }`，添加成功返回 204；重复提交不会重复添加 |
| DELETE | `/api/v1/artists/{id}/search-aliases/{aliasId}` | 删除该歌手及其合并来源的指定人工别名，成功返回 204 |

别名须为去除首尾空格后 1–200 个字符。不存在的歌手或不属于该歌手的别名返回 404，无效输入返回 400。会话认证的 API 写入须提供 `X-CSRF-Token`；Bearer Token 沿用已有鉴权规则。

Web 中在歌手资料页的“搜索别名”维护人工名字，外部来源别名单独展示。人工搜索别名独立保存，不受外部刷新覆盖，也不进入身份自动匹配或元数据增强。数据库迁移 071 创建别名表，无需联网回填；已有外部别名在搜索时直接可用。

`/api/v1/capabilities` 增加 `unifiedSearch`、`artistSearchAliases` 能力标志。
