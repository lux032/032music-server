# Spec Delta

## Purpose

定义 032 Music Server 管理员首次登录后的 5 步初始化引导能力，涵盖全新部署暂缓首次自动扫描直至向导完成或跳过、向导状态持久化与老实例升级兼容、分步写入既有配置表与只写密钥保护、页内异步连通性测试与目录只读预检、按需浮现的部署风险提醒及跳过续配与随时重入机制。

## ADDED Requirements

### Requirement: 首次登录触发初始化引导且保持认证与深链边界
所有 `/admin/setup` 页面与接口 SHALL 要求管理员已登录鉴权，未认证请求沿用既有登录重定向或拒绝策略。当初始化状态为 `pending` 时，已认证管理员访问默认着陆页（`/admin` 与 `/admin/home`）SHALL 重定向至 `/admin/setup`；直接访问非着陆管理页（如 `/admin/settings/security`）SHALL 正常渲染而不被循环拦截。

#### Scenario: 全新部署首次登录后自动进入初始化引导
- **WHEN** 管理员在初始化状态为 `pending` 的全新数据库上登录成功并访问 `/admin` 或 `/admin/home`
- **THEN** 服务端返回 `303 See Other` 重定向至 `/admin/setup`

#### Scenario: 未登录访问初始化引导及接口被拦截
- **WHEN** 未认证客户端请求 `GET /admin/setup` 或 `POST /admin/setup/step/1`
- **THEN** 请求被重定向至 `/admin/login` 或返回未认证错误，不泄露或修改任何配置

#### Scenario: 待初始化状态下直接访问特定设置页不被死循环拦截
- **WHEN** 已认证管理员在 `pending` 状态下直接打开 `/admin/settings/security`
- **THEN** 页面正常渲染账号与安全设置，不重定向回 `/admin/setup`

### Requirement: 老实例升级自动判定为已完成且不打扰
数据库迁移 SHALL 在检测到既有音频文件、历史扫描记录，或已配置的元数据、AI、联网搜索、播放同步或资源获取设置时，将初始化状态初始化为 `completed`；仅在全新空库上初始化为 `pending`。

#### Scenario: 老实例升级后登录不弹出初始化引导
- **WHEN** 已包含曲库文件、历史扫描任务或既有元数据/AI 配置的数据库升级至引入向导的迁移版本
- **THEN** 向导状态自动初始化为 `completed`，管理员访问 `/admin` 与 `/admin/home` 正常渲染，不跳转 `/admin/setup`

#### Scenario: 全新空库初始化为待引导状态
- **WHEN** 迁移在全新的空 SQLite 数据库上执行完毕
- **THEN** 向导状态初始化为 `pending` 且当前步骤为第 1 步

### Requirement: 全新部署暂缓首次自动扫描直至向导完成或跳过
当服务端启动且初始化状态为 `pending` 时，系统 SHALL 暂缓启动自动首次扫描与后台目录轮询监控。管理员在第 5 步点击「完成配置并启动首次扫描」或点击「暂不配置，直接扫描入库」时，系统 SHALL 激活目录监控并立即发起首次增量扫描；选择「仅保存配置，稍后手动扫描」时 SHALL 标记为 `completed` 并保存监控策略而不立即启动扫描。

#### Scenario: 待初始化状态下启动不提前触发首次扫描
- **WHEN** 服务端在初始化状态为 `pending` 的全新数据库上启动
- **THEN** 后台不启动首次自动扫描，也不进行全目录初始指纹遍历

#### Scenario: 完成第 5 步启动首次扫描并串联已配置流水线
- **WHEN** 管理员在目录预检通过、勾选「扫描完成后自动执行增强与后台任务」的状态下点击「完成配置并启动首次扫描」
- **THEN** 向导状态更新为 `completed`，目录监控按所选间隔启用，首次增量扫描立即启动，且扫描结束后自动唤醒已配置的元数据增强与已启用的后台任务

#### Scenario: 第 5 步取消自动串联时首次扫描仅导入本地标签
- **WHEN** 管理员在第 5 步取消勾选「扫描完成后自动执行增强与后台任务」并启动首次扫描
- **THEN** 本次首次扫描仅导入音频本地标签，不自动触发远程元数据增强或 AI 后台队列，后续扫描恢复常规自动化行为

#### Scenario: 跳过引导立即解除扫描暂缓
- **WHEN** 管理员在向导页点击「暂不配置，直接扫描入库」
- **THEN** 向导状态更新为 `skipped`，立即启动目录监控与首次增量扫描，并跳转至 `/admin`

#### Scenario: 已完成状态的老实例保持启动即扫行为不变
- **WHEN** 服务端在初始化状态为 `completed` 的数据库上启动
- **THEN** 首次增量扫描与目录监控在启动时立即按原有策略执行

### Requirement: 五步分步配置直写既有配置表并保证密钥只写
向导 SHALL 按顺序提供 5 个可独立保存、单步跳过与随时回改的步骤——（1）元数据与图源、（2）LLM 与联网搜索、（3）自动化能力、（4）同步与资源获取（可选）、（5）曲库与启动扫描，并将数据直接写入既有权威设置表。已保存的 API Key、Token 与密码 SHALL 绝不明文回显，留空重新保存时 SHALL 保留原有密钥。

#### Scenario: 启用 MusicBrainz 但未填联系信息时行内拦截
- **WHEN** 管理员在第 1 步启用 MusicBrainz 且联系邮箱或项目地址为空时提交保存
- **THEN** 服务端拒绝保存并返回指向联系信息字段的结构化校验错误，保留其他已填内容且不推进步骤

#### Scenario: 刷新或回访第 2 步时不回显明文密钥且留空保留
- **WHEN** 管理员在第 2 步保存 LLM API Key 与多把 Tavily Key 后刷新页面或重新访问第 2 步
- **THEN** 页面仅展示「已配置」状态与 Tavily Key 数量而不返回明文，再次保存且密钥输入框留空时原密钥完整保留

#### Scenario: 跨步骤自动复用 DeepSeek 联网密钥与 Last.fm API Key
- **WHEN** 管理员在第 2 步配置 DeepSeek 官方接口，或在第 1 步填写 Last.fm API Key
- **THEN** 第 2 步联网搜索区展示已自动复用 DeepSeek 密钥提示，第 4 步 Last.fm Scrobble 自动复用第 1 步的 API Key（若直接在第 4 步填写则同步写回第 1 步）

### Requirement: 自动化能力按前置依赖动态锁定并提供场景预设
第 3 步 SHALL 根据前两步已保存配置及声学分析 Sidecar 检测结果动态展示前置就绪状态，提供「纯本地保守」「ACG 推荐组合」「全自动拉满」三套预设，对未满足前提的功能锁定开关并提供跳回对应步骤的入口，且在 `pending` 状态下不提前唤醒耗费额度的后台队列。

#### Scenario: 缺少 LLM 或声学分析容器时锁定对应开关
- **WHEN** 管理员在未配置 LLM 或未部署 `music-analyzer` 容器的情况下进入第 3 步
- **THEN** 依赖 LLM 的开关与本地声学分析开关呈锁定状态，标明缺失前提并提供直接跳回第 2 步配置模型的快捷入口

#### Scenario: AI 曲库打标明确提示批量消耗且默认保守关闭
- **WHEN** 管理员已配置 LLM 并进入第 3 步
- **THEN** 在「纯本地保守」与「ACG 推荐组合」预设下 AI 曲库打标保持关闭，行内清晰提示每首约 2,000 token 的全库批量消耗

### Requirement: 页内异步连通性测试与有界只读目录预检
向导 SHALL 提供带 CSRF 校验的管理员 JSON 端点，支持在不刷新页面的前提下测试 LLM 连接、联网搜索、ListenBrainz 账号验证、Last.fm 两步 OAuth 授权、Jackett、qBittorrent 以及音乐目录有界只读预检。目录预检 SHALL 在不触发全库扫描的前提下校验目录是否存在、可读及是否包含内容。

#### Scenario: 第 2 步页内测试返回结构化结果且不丢失未保存表单
- **WHEN** 管理员在第 2 步点击「测试模型连接」或「测试联网搜索」
- **THEN** 服务端优先使用请求提交参数（留空密钥回退已存密钥）执行连通性探测，返回包含状态、耗时或可操作错误的 JSON，页面就地展示结果且保留所有表单输入

#### Scenario: 第 5 步目录预检在空目录或无权限时阻断直接启动扫描
- **WHEN** 音乐目录缺失、无读取权限或为空目录，管理员进入第 5 步或点击「重新检测目录」
- **THEN** 预检端点返回具体排查指引，前端禁用「完成配置并启动首次扫描」直至检测通过，同时保留「仅保存配置，稍后手动扫描」可用

### Requirement: 部署提醒按需浮现、跳过续配提示与永久重入
未受信反向代理或临时生成 Media Token 等真实部署风险 SHALL 仅在检测到异常时显示于向导顶部，健康部署不增加额外只读步骤。跳过向导后 `/admin` SHALL 展示可持久化关闭的续配提示条，且 `/admin` SHALL 始终保留手动重新打开 `/admin/setup` 的入口而不重新拦截登录或暂停目录监控。

#### Scenario: 健康部署打开向导无顶部告警条
- **WHEN** 管理员在无未受信反向代理且已配置固定 Media Token 的实例上打开 `/admin/setup`
- **THEN** 向导直接呈现第 1 步「元数据与图源」，顶部不显示部署风险提醒条

#### Scenario: 跳过向导后控制台展示可关闭续配条并保留重开入口
- **WHEN** 管理员跳过向导进入 `/admin` 并点击提示条上的「不再提示」
- **THEN** 关闭状态持久化存储，后续刷新 `/admin` 不再显示提示条，但页面仍保留「重新打开初始化向导」入口

#### Scenario: 已完成实例重开向导修改配置不影响正常运行
- **WHEN** 已完成初始化的管理员从 `/admin` 点击「重新打开初始化向导」，修改第 2 步后返回 `/admin`
- **THEN** 向导状态保持 `completed`，目录监控持续运行，访问 `/admin` 不会再次跳转 `/admin/setup`

### Requirement: 专注态界面遵循项目设计体系并适配移动端
`/admin/setup` SHALL 采用隐藏曲库侧栏与底部播放栏的独立专注态壳层，严格复用 `tokens.css` 浅色/深色双主题令牌、单紫强调色与 1px 平面细线面板规范，在 `<= 900px` 视口下折叠为顶部横向步骤条并保证零横向溢出。

#### Scenario: 移动端视口下步骤栏与表单无横向溢出
- **WHEN** 在 `390x844` 视口下以浅色或深色主题渲染 `/admin/setup`
- **THEN** 左侧步骤轨转为可横向滚动的顶部步骤条，多列表单堆叠为单列，页面文档宽度不超过视口宽度
