# Spec Delta

## Purpose

定义艺术家全量存量头像 AI 视觉审查、高置信自动多源获取与替换、按问题类型差异化清理、双黑名单与幂等防重审、一键撤销快照、缓存 URL 版本刷新及新型 GPT 温度兼容与非静默失败的行为规范。

## ADDED Requirements

### Requirement: 全量存量头像 AI 视觉审查与按内容哈希幂等跳过
系统 SHALL 在持久化头像补全任务中提供全量审查模式（`audit_all`）与强制重审模式（`audit_force`），覆盖全库无自定义头像的未合并艺人；对已有缓存头像先校验本地文件完整性与尺寸比例，再调用视觉模型输出结构化判定，并对审查通过的当前 `content_hash` 持久化防重审记录。

#### Scenario: 始终保护人工自定义头像不被审查或替换
- **WHEN** 全量审查任务（含 `audit_force`）扫描全库艺人，其中部分艺人本人或其合并来源存在 `artist_custom_images` 记录
- **THEN** 系统自动排除这些艺人，既不对其发起 VLM 审查，也不覆写或清理其自定义头像

#### Scenario: 已审查通过且哈希未变的存量头像在普通全量模式下幂等跳过
- **WHEN** 某艺人当前有效缓存头像的 `content_hash` 在 `artist_image_reviews` 中已存在 `verdict='keep'` 记录，且管理员再次启动 `audit_all`
- **THEN** 系统直接跳过该艺人而不重复调用 VLM 模型；仅当管理员显式选择 `audit_force` 或该艺人头像变更为新哈希时才重新审查

#### Scenario: 存量头像在本地读盘损坏或尺寸不合规时零成本判为垃圾图
- **WHEN** 审查任务读取某艺人已存在的缓存文件发现文件损坏、无法解码或分辨率/宽高比不满足头像质量基线
- **THEN** 系统不消耗视觉模型 token，直接按高置信 `garbage` 进入自动获取与替换流程

#### Scenario: 存量头像审查返回结构化分类与置信度并记录独立用量
- **WHEN** 审查任务对合法缓存图片调用多模态模型，传入艺人身份锚点、代表作及当前图片来源信息
- **THEN** 系统解析模型输出的 `verdict`、`issueType`、`confidence`（0–100）与 `reason`，并将本次模型用量以 `artist_image_audit` 用途计入 `ai_usage`

### Requirement: 高置信判错自动多源获取并全链路校验替换新图
当存量头像被高置信判定需要替换（`verdict='replace'` 且 `confidence >= audit_auto_confidence`）时，系统 SHALL 将旧图 URL 与 `content_hash` 纳入排除集并依次执行 Tier 1–3 重抓；所有重抓候选图（含结构化图源）均须通过 VLM 质量复核，仅在双高置信时自动替换入库。

#### Scenario: 排除旧图 URL 与内容哈希防止结构化图源反复回抓同一错图
- **WHEN** 某艺人原有 Deezer 或 Bangumi 头像被高置信判错并触发自动重抓，而原图源或其他图源再次返回相同 URL 或相同 `content_hash` 的图片
- **THEN** 重抓流程跳过该候选并继续尝试后续图源，避免将同一张错图重新写回缓存

#### Scenario: 重抓获得高置信合格新图时自动替换缓存并锁定旧图黑名单
- **WHEN** 自动重抓在任一图源下载到未命中排除集的候选图，且 VLM 复核判定合格且达到高置信阈值（并启用高置信自动应用）
- **THEN** 系统在带写锁与 checkpoint 校验的事务内更新 `artist_image_cache`，将旧图 URL 与 `content_hash` 写入拒绝表，记录新图已审通过标记，并留存可撤销替换快照

#### Scenario: 重抓仅获得中置信新图或未开启自动落库时送入新旧对比待审
- **WHEN** 自动重抓仅找到中置信候选图，或管理员关闭了「高置信度结果自动入库」
- **THEN** 系统保留当前旧头像不变，缓存候选图预览并写入待审头像队列，供管理员在「待审头像」页面并排对比旧图与新候选图后决策

### Requirement: 无替代图时按问题类型差异化处理与中低置信省额策略
当高置信判错但全源均未找到合格替代图时，系统 SHALL 仅对 `garbage` 自动清空旧缓存（含合并源继承缓存），对其他问题类型保留旧图并推送人工待审；当审查为中/低置信疑点时，系统 SHALL 默认保留旧图并推送待审而不自动触发联网搜图。

#### Scenario: 明确垃圾图无替代图时自动清空主艺人及合并源继承缓存
- **WHEN** 旧图被高置信判定为 `garbage`（Logo、灰人占位符、纯文字横幅、损坏或完全无关场景），且 Tier 1–3 均未找到合格新图
- **THEN** 系统在事务内快照并删除该艺人及其合并来源艺人的 `artist_image_cache` 行，拉黑旧图并写入负缓存冷却，使客户端回退显示默认头像

#### Scenario: 专辑封面低画质或疑似错人无替代图时保留旧图并送人工复核
- **WHEN** 旧图被高置信判定为 `album_cover`、`low_quality` 或 `wrong_subject`，且全源未找到合格替代图
- **THEN** 系统保留旧缓存头像不删除，并将该艺人作为 `audit_review` 项写入待审头像列表（附 AI 判错类型与理由），支持管理员手动保留、清空或再次联网搜图

#### Scenario: 中低置信疑点旧图默认不自动消耗联网搜索额度
- **WHEN** 视觉模型判定 `verdict='replace'` 但 `confidence` 低于高置信阈值（默认 `< 85`）
- **THEN** 系统不自动发起联网搜图与替换，保留当前旧图并生成 `audit_review` 待审卡片，管理员可在卡片上按需点击「保留原图」「清空头像」或「联网找新图」

### Requirement: 自动替换与清理提供快照一键撤销及缓存版本即时刷新
系统 SHALL 为每次自动替换或自动清理持久化完整的旧缓存快照，支持管理员一键撤销并防止下次审查重复误替；所有自动缓存头像 URL SHALL 附带基于内容哈希的版本查询参数以保证客户端即时刷新。

#### Scenario: 管理员一键撤销自动替换或自动清理恢复原头像
- **WHEN** 管理员在管理页对某条未撤销的自动替换或自动清理记录点击「撤销」，且目标艺人未合并且无并发新增的自定义头像
- **THEN** 系统在事务内按快照还原原有 `artist_image_cache` 行（含合并源归属）、移除对应旧图黑名单、将该旧图哈希标记为已人工确认保留，并将审计记录置为 `reverted=1`

#### Scenario: 存在并发自定义头像时撤销操作安全拒绝
- **WHEN** 某艺人在 AI 自动替换或清理后被管理员手工上传了自定义头像，随后尝试撤销该条旧审计记录
- **THEN** 系统拒绝覆写自定义头像并返回明确的状态冲突提示

#### Scenario: 自动缓存头像替换后接口输出带哈希版本号的 URL
- **WHEN** 任意列表、详情或管理接口通过 `artistImageURLSQL` 查询已缓存头像艺人的展示地址
- **THEN** 返回地址为 `/api/v1/artists/{id}/image?v=<content_hash前12位>`，头像被自动替换或撤销后 URL 版本立即变化以绕过浏览器与客户端旧缓存

### Requirement: LLM 温度参数自动兼容与审查链路非静默失败
系统 SHALL 在 OpenAI 兼容 Chat 请求因 `temperature` 参数被服务端拒绝（HTTP 400）时自动省略 `temperature` 重试一次；头像审查与重抓 VLM 验收遇模型请求或解析失败时 SHALL 明确报错失败而非静默放行。

#### Scenario: 模型拒收零温参数时自动省略 temperature 重试成功
- **WHEN** `ChatClient.Complete` 向某新版或推理型 GPT 模型发送携带 `"temperature": 0` 的请求，服务端返回 HTTP 400 且错误消息指明不支持 `temperature`
- **THEN** 客户端自动移除 `temperature` 字段重试一次并在成功返回结果的同时记录该模型省略温度偏好，后续调用无需重复触发 400

#### Scenario: VLM 审查或重抓验收遇 400 或解析失败时不静默放行
- **WHEN** 存量头像审查或重抓新图 VLM 验收收到模型 HTTP 400、鉴权失败、超时或非法 JSON 响应
- **THEN** 对应任务项明确记录 `failed` 与脱敏错误原因，保留艺人原有头像且不写入已审通过记录，绝不将该图片当作 `valid=true` 静默放行
