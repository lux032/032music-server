# Spec Delta

## MODIFIED Requirements

### Requirement: 待审头像联网搜索状态持久化标记与异步批量找图队列
系统 SHALL 在 `artist_image_candidates` 中持久化联网搜索状态与说明，区分未搜过、自动审查已搜无果、手动联网已搜无果与搜图失败，并提供独立于全量补全任务的后端串行异步手动找图队列及管理页多选批处理工作台；管理页表单交互 SHALL 在 PJAX 环境下正确传递选中候选集合、避免重复提交与轮询误重置，并按实际结果分类返回反馈。

#### Scenario: 自动审查高置信疑点实际联网无果时持久化标记为自动已搜无果
- **WHEN** 高置信非垃圾疑点在全量审查重抓阶段实际执行了 Tier 3 联网搜索且仍未找到合格替代图
- **THEN** 系统在写入 `audit_review` 待审卡片时同步持久化 `web_search_state='not_found_auto'` 与说明文本；若因单轮联网预算耗尽或未配置联网而未执行 Tier 3，则保持 `web_search_state=''`

#### Scenario: 手动联网找图无结果或失败后在卡片上持久展示标记且不锁死重试
- **WHEN** 管理员通过队列对某张 `audit_review` 待审卡片发起手动联网找图，而联网未找到更合适的候选图或发生网络/模型错误
- **THEN** 系统在对应 `artist_image_candidates` 记录持久化 `not_found_manual` 或 `failed` 状态、脱敏说明与搜索时间，刷新页面后卡片仍清晰显示状态图标并将找图按钮降级为「重新搜图」允许再次重试

#### Scenario: 多选批量加入后台异步队列并支持运行中追加、移出与停止
- **WHEN** 管理员在「待审头像」页多选（或使用「仅选未搜过」）若干待审卡片加入联网找图队列
- **THEN** 后端独立串行队列（并发 1、不受全量任务单轮联网上限约束）按入队顺序执行搜图，前端实时展示队列进度条与每张卡片的「排队中 #N」「搜图中」图标；运行期间允许继续追加新卡片、移出单条未开始项或一键停止队列，切换页签或刷新页面不中断执行

#### Scenario: 单卡联网找新图在 PJAX 环境下原地入队且不触发重复提交或整页刷新
- **WHEN** 管理员在启用 PJAX 的「待审头像」页点击单张 `audit_review` 卡片的「联网找新图」或「重新搜图」
- **THEN** 前端仅发起一次异步入队请求并原地更新顶部队列条与该卡片状态，不触发重复表单提交或 PJAX 整页替换，也不丢失其余卡片的勾选与筛选状态

#### Scenario: 队列搜到新候选图后原地收口原疑点卡为单张新旧图对比卡
- **WHEN** 手动联网找图队列为某张 `audit_review` 待审卡片成功发现并通过质检的新候选头像
- **THEN** 系统在单事务内创建 `replacement` 对比卡片（继承原问题分类）并关闭原 `audit_review` 记录，使同一艺人在「待审头像」列表只展示一张「当前旧图 vs 新候选图」对比卡，提供「采纳替换」「保留原图」「清空头像」「忽略」操作

#### Scenario: 多选支持批量保留原图与带二次确认的批量清空头像
- **WHEN** 管理员在启用 PJAX 的「待审头像」页多选待审卡片执行「批量保留原图」，或先点击「批量清空头像」进入二次确认态后再点击确认按钮提交
- **THEN** 提交请求在被 PJAX 路由序列化前已携带全部已选待审项 ID，后端按既有单卡语义逐项落库（保留原图写入 `keep` 防重审标记，清空头像保护并发自定义头像并留存可撤销快照），刷新后已处理卡片从列表移除并返回实际处理数量反馈

#### Scenario: 批量清空二次确认在找图队列轮询期间保持武装态不被误重置
- **WHEN** 手动联网找图队列正在运行且触发定时轮询刷新，期间管理员已点击「批量清空头像」进入二次确认态且当前已选待审项集合未发生变化
- **THEN** 定时轮询不得解除该按钮的二次确认武装态或移除「取消」按钮；仅当已选待审项集合发生变化（增减或因入队/状态变化导致勾选缩减/归零）时才重置确认态

#### Scenario: 批量保留与批量清空按空选、已处理、自定义头像保护与失败分类反馈
- **WHEN** `batch-clear` 或 `batch-keep` 端点收到批量请求
- **THEN** 若请求未包含任何有效待审项 ID，返回明确空选提示（如「未选中任何待审项」），不得误报「存在自定义头像」；若包含待审项 ID，后端按实际发生的已处理数、已提前处理/不存在跳过数、并发自定义头像保护跳过数与真实执行失败数分类统计，并仅在对应情况实际发生时于提示文案中提及该原因
